# MBappe

MBappe — учебный MVP desktop-приложение для управления персоналом. Проект разработан на C# с использованием Avalonia UI, .NET 9, MVVM-подхода, SQLite и Entity Framework Core.

Система предназначена для работы с учетными записями, сотрудниками, KPI, обучением, мотивацией, аналитикой и журналом действий.

## Основные возможности

В проекте реализованы следующие модули:

- авторизация и регистрация пользователей;
- ролевая модель доступа;
- управление пользователями;
- управление сотрудниками;
- журналирование действий;
- управление KPI;
- расчет эффективности сотрудников;
- модуль обучения;
- модуль мотивации и бонусов;
- аналитика и отчетность;
- хранение данных в SQLite через Entity Framework Core;
- автоматические тесты для проверки ключевой логики.

## Роли пользователей

В системе используются четыре основные роли:

| Роль | Назначение |
|---|---|
| Employee | Просмотр личного профиля, своих KPI, обучения и бонусов |
| Manager | Работа с данными своей команды |
| HrSpecialist | Управление сотрудниками, обучением, KPI и мотивацией |
| Administrator | Полный доступ к системе, пользователям, журналу и данным |

## Тестовые учетные записи

При первом запуске база данных автоматически заполняется тестовыми пользователями:

| Логин | Пароль | Роль |
|---|---|---|
| admin | 12345 | Administrator |
| hr | 12345 | HrSpecialist |
| manager | 12345 | Manager |
| employee | 12345 | Employee |

## Архитектура проекта

Проект построен по модульному принципу. Основная логика разделена между моделями, сервисами, репозиториями и ViewModel.

Общая схема работы приложения:

```text
View
 ↓
ViewModel
 ↓
Service
 ↓
Repository Interface
 ↓
EF Repository
 ↓
SQLite Database
```

Такой подход позволил сначала разрабатывать бизнес-логику на in-memory-репозиториях, а затем перейти на постоянное хранение данных через SQLite без переписывания сервисного слоя.

## Основная структура проекта

```text
MBappe/
├─ Common/          # DTO, request/result-классы
├─ Data/            # AppDbContext и инициализация базы данных
├─ Models/          # Основные модели предметной области
├─ Repositories/    # Интерфейсы и реализации репозиториев
├─ Services/        # Бизнес-логика приложения
├─ ViewModels/      # ViewModel для Avalonia MVVM
├─ Views/           # Экраны Avalonia UI
└─ Tests/           # Автоматические тесты
```

## Реализованные модули

### Авторизация и регистрация

Модуль отвечает за вход пользователей в систему, регистрацию, проверку логина и пароля, хранение текущей сессии и проверку активности учетной записи. Пароли не хранятся в открытом виде: используется хеширование с солью.

### Пользователи и сотрудники

В проекте разделены две сущности:

- `AppUser` — учетная запись для входа в систему;
- `EmployeeProfile` — кадровый профиль сотрудника.

Такое разделение позволяет отдельно хранить данные авторизации и кадровую информацию: должность, отдел, табельный номер, руководителя, дату приема и статус сотрудника.

### KPI

Модуль KPI позволяет назначать сотрудникам показатели эффективности, указывать плановое и фактическое значение, вес KPI, период оценки и статус. Процент выполнения рассчитывается автоматически.

### Обучение

Модуль обучения поддерживает создание учебных курсов, назначение курсов сотрудникам, обновление прогресса и фиксацию результата прохождения.

### Мотивация

Модуль мотивации связан с KPI. Система рассчитывает эффективность сотрудника за период и на основе мотивационной программы определяет размер бонуса. Поддерживаются статусы начислений: ожидание утверждения, утверждено, отклонено, выплачено и отменено.

### Аналитика

Модуль аналитики собирает данные из сотрудников, KPI, обучения и мотивации. На экране отображаются сводные показатели и таблица по сотрудникам, что позволяет оценить состояние персонала и выявить проблемные зоны.

### Журнал действий

Важные операции пользователей фиксируются в журнале: вход, ошибки авторизации, создание и изменение данных, действия с KPI, обучением, мотивацией и доступом.

## Хранение данных

Для постоянного хранения используется SQLite. База данных создается автоматически при первом запуске приложения.

Файл базы данных хранится в пользовательской папке приложения:

```text
%LOCALAPPDATA%\MBappe\mbappe.db
```

Для создания базы используется `DatabaseInitializer`, который вызывает `EnsureCreatedAsync()` и добавляет стартовые данные.

## Установка и запуск

Перед запуском должен быть установлен .NET SDK 9.

Сборка проекта:

```bash
dotnet build
```

Запуск приложения:

```bash
dotnet run --project MBappe
```

Если решение содержит несколько проектов, запуск можно выполнить из проекта приложения или через Visual Studio.

## Тестирование

Запуск автоматических тестов:

```bash
dotnet test
```

Тесты проверяют ключевую бизнес-логику: авторизацию, работу сервисов, репозитории, аналитику и навигацию.

## Ограничения MVP

Текущая версия является учебным MVP. В проекте не реализованы:

- интеграция с Moodle;
- интеграция с 1С;
- LDAP/OAuth-авторизация;
- LLM-интеграция;
- экспорт отчетов в PDF/Excel;
- полноценные EF Core миграции;
- production-развертывание;
- расширенная система резервного копирования и шифрования базы.

Эти возможности могут быть добавлены на следующих этапах развития проекта.
